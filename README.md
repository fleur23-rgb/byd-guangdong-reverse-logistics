# 比亚迪广东退役动力电池逆向物流网络模型

这是一个面向学术复核和方案比较的 Python 混合整数线性规划（MILP）项目。它把广东省退役动力电池的来源地、区域回收/检测中心、梯次利用设施、再生利用设施和运输线路放在同一个网络中，回答一个实际规划问题：**在给定回收规模、设施能力、服务半径和成本参数下，应该选哪些节点、如何分配流量，以及需要多少应急外包，才能使网络更可靠、年度成本更低？**

本仓库只发布模型、数据、结果和可视化网站源码，不发布论文 Word/PDF 稿件。

> 重要边界：仓库中的数据包含公开资料估计、空间代理、文献校准参数和情景假设，不是比亚迪内部经营台账。模型输出是研究情景下的规划结果，不代表比亚迪的实际网络、实际成本、实际盈利或降本承诺。

## 为什么标题这样写

- **“比亚迪广东”**：研究案例的业务背景和空间范围是广东省比亚迪退役动力电池回收网络；
- **“退役动力电池”**：模型处理的是车辆退役后进入回收、检测、梯次利用或再生利用环节的电池总量；
- **“逆向物流网络”**：物流方向与传统销售物流相反，从来源地回流到回收中心和后端处理设施；
- **“模型”**：这里发布的是可运行的决策模型和复现材料，不是企业官方软件或企业数据接口。

因此，这个标题用于准确说明研究对象和模型用途，并不表示本项目由比亚迪官方发布或代表比亚迪作出经营判断。

## 模型解决什么问题

模型将网络抽象为三层：

```text
21 个广东来源/汇聚区域
        ↓ 前端回收、检测与集散
区域回收中心（自建或委托）
        ├── 梯次利用设施
        └── 再生利用设施（含现有 P01）
        ↓
无法由正常网络承接的部分 → 应急外包
```

给定一组情景参数后，模型同时决定：

1. 开设哪些区域中心，以及采用自建还是委托方式；
2. 开设哪些梯次利用、再生利用设施，是否选择 P01；
3. 是否对 P01 进行 2,000 吨或 5,000 吨级别的扩容；
4. 每个来源区域向哪个中心运输多少电池；
5. 每个中心向梯次利用和再生利用设施分别分配多少流量；
6. 正常网络无法承接的数量和应急外包比例。

模型包含来源—中心、中心—梯次设施、中心—再生设施三类运输弧，并可切换代理距离和 OSRM `driving/car` 路网距离。主要约束包括流量守恒、节点容量、共享实体容量、服务半径、候选弧、最低处理量、梯次/再生分流比例和 P01 扩容限制。

目标采用词典序两阶段优化：第一阶段先把应急外包量压到最低；第二阶段在达到该最低外包量的条件下，再最小化年度总成本。年度成本包括设施固定成本、回收与处理作业费、运输费、P01 扩容费和应急外包费。

## 基准情景示例

仓库中的 `results/scenario_summary.csv` 保存了正式情景结果。以 `baseline` 行为例，模型输入的网络进入量为 3,516.584 吨，正常网络处理约 3,210.991 吨，应急外包约 305.593 吨（8.69%），年度总成本约 6,882.25 万元。该数值是公开代理数据下的基准情景结果，不能直接解释为企业真实经营数据。

## 输入、计算与输出

**输入**主要包括：

- 21 个来源区域及退役量估计；
- 区域中心候选点、容量、组织方式和固定/单位成本；
- 梯次利用、再生利用和 P01 设施参数；
- Haversine 代理距离、OSRM 路网距离和服务半径；
- 承接率、梯次利用比例、容量系数、最低处理量和扩容成本系数；
- `configs/` 中定义的基准情景与敏感性情景。

**输出**主要包括：

- 每组情景的总成本、单位成本、正常处理量和应急外包量；
- 选中的区域中心、后端设施及其利用率；
- 各运输弧的流量、距离和吨公里；
- 约束校验、求解状态和情景对比结果；
- 基准网络图、成本构成图和敏感性图。

## Python 模型复现

要求 Python 3.11 或更高版本，并使用 HiGHS 求解器：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-lock.txt
python scripts/reproduce_results.py
python -m pytest -q
```

如果只想运行单个基准情景，可以查看 `scripts/run_baseline.py`；批量情景入口是 `scripts/run_scenarios.py`。如需从工作簿重新生成规范化输入：

```bash
python scripts/reproduce_results.py --workbook "/path/to/广东省动力电池闭环供应链论文数据集_V2.1.xlsx"
```

正式情景使用 OSRM 路网距离；代理距离只用于诊断和敏感性比较。结果默认写入 `results/`，模型不会自动修改原始工作簿。

## 可视化网站

在线地址：<https://fleur23-rgb.github.io/byd-guangdong-reverse-logistics/>

网站面向非代码读者，提供两个用途：

- 加载“广东省·论文参考案例”预设，直观看到节点数量、处理能力、应急外包和成本构成；
- 调整退役量、承接率、服务半径、运输距离、设施成本等参数，快速比较参数变化的方向和幅度。

网站中的即时计算是为了交互展示而设计的参数化近似，不替代 `src/` 中使用 Pyomo + HiGHS 的完整 MILP 求解。需要论文级复核时，应运行 Python 模型并检查 `validation.json`。

## 复核状态与已知限制

- 已保存 49 组正式 OSRM 情景和 1 组代理距离对照情景；
- 测试覆盖输入、流量平衡、候选弧、设施容量、共享实体容量、距离、成本和应急外包等约束；
- 设施坐标多数为地市级代理点，运输距离不是企业实际调度轨迹；
- 模型是单期、单类总量规划模型，未纳入真实回流台账、电池健康状态、完整危运路线、供应商合同能力、收购价、产品销售收入和多期库存；
