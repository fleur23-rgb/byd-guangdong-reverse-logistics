# 全国退役动力电池逆向物流网络优化模型

一个面向中国不同省份、城市群及跨区域场景的退役动力电池逆向物流网络规划框架，使用 Python、Pyomo 和 HiGHS 构建混合整数线性规划（MILP）模型。仓库内置“比亚迪广东案例”作为首个完整的数据示范与复现情景，但广东不是模型的适用边界。

[在线使用可视化工具](https://fleur23-rgb.github.io/china-ev-battery-reverse-logistics/) · [查看广东示范数据](data/README.md) · [查看情景结果](results/scenario_summary.csv)

> 项目定位：全国通用的是网络结构、决策变量、约束体系、成本核算和数据接口；仓库当前完成实证校准与结果验证的是广东情景。模型不包含全国各地区的现成实测数据库，应用到其他地区时需要替换当地数据。

## 这是什么

动力电池退役后，需要从车辆使用地或回收来源地反向流向回收检测中心，再进入梯次利用或再生利用设施。规划者通常需要同时回答以下问题：

- 区域回收中心应该设置在哪里、设置多少个；
- 各中心应采用企业自建还是委托合作模式；
- 哪些梯次利用和再生利用设施应被纳入网络；
- 不同地区的退役电池应经过哪些节点、运输多少；
- 当正常网络能力不足时，需要多少应急外包；
- 服务半径、处理能力、运输价格和回收规模变化时，网络方案是否仍然可行。

本项目把这些选址、分配和容量问题放进同一个优化模型中，输出满足约束条件的网络方案及其年度成本。它适合用于论文复现、区域规划、企业方案预评估、参数敏感性分析和教学演示。

## 为什么仓库名里有 BYD 和 Guangdong

仓库最初围绕“比亚迪广东退役动力电池回收案例”建立，现已更名为 `china-ev-battery-reverse-logistics`，以体现全国可配置框架的定位。现有数据文件仍以广东案例为主：

- **通用层**：来源节点、候选中心、后端设施、运输弧、容量、成本、服务半径、分流和应急外包逻辑；
- **案例层**：广东 21 市、比亚迪业务背景、汕尾 P01 设施及广东情景参数；
- **应用层**：通过替换标准化输入和情景配置，将同一框架用于其他省份、城市群或全国分区网络。

因此，更准确的项目标题是“全国退役动力电池逆向物流网络优化模型”，比亚迪广东是当前内置示范情景，而不是模型只能服务的对象。本项目不是比亚迪官方软件，也不代表比亚迪作出经营判断。

## 网络结构

```text
任意数量的来源区域
        │
        │ 退役电池回流、运输距离与服务半径
        ▼
候选区域回收/检测/集散中心
        │ 自建或委托、容量和最低处理量
        ├──────────────────┐
        ▼                  ▼
梯次利用设施          再生利用设施
        │                  │
        └────────┬─────────┘
                 ▼
       正常网络无法承接的部分
             应急外包
```

在广东示范情景中，来源区域为广东 21 市，后端设施包含汕尾 P01；更换地区时，来源节点、候选中心和处理设施的数量均可通过数据表调整。

## 模型作出哪些决策

给定区域数据和情景参数后，模型决定：

1. 开设哪些区域回收中心；
2. 每个中心采用自建还是委托模式；
3. 启用哪些梯次利用和再生利用设施；
4. 每个来源节点向哪个回收中心分配多少流量；
5. 各中心向梯次利用和再生利用设施分别分配多少流量；
6. 案例指定设施是否扩容以及扩容级别；
7. 正常网络无法承接的应急外包量。

## 优化目标与主要约束

默认采用词典序两阶段优化：

1. 第一阶段优先最小化应急外包量，避免模型仅因成本较低而主动放弃正常网络处理；
2. 第二阶段固定第一阶段得到的最低外包水平，再最小化年度总成本。

年度总成本由区域中心固定成本、后端设施固定成本、回收检测作业费、梯次/再生处理费、运输费、扩容费和应急外包费构成。

主要约束包括：

- 来源节点、区域中心和后端设施的流量守恒；
- 区域中心及处理设施容量；
- 同一物理企业下不同功能节点的共享容量；
- 来源—中心、中心—梯次设施和中心—再生设施服务半径；
- 候选运输弧可达性；
- 中心和合作设施最低处理量；
- 梯次利用与再生利用分流比例；
- 设施启用数量、组织方式和指定设施扩容条件。

## 如何应用到全国或其他地区

模型不是把广东数据简单放大到全国，而是提供统一的数据接口。迁移到其他地区通常需要完成五步：

1. 在 `regions.csv` 中写入新的来源区域、坐标和退役量；
2. 在 `collection_options.csv` 中设置候选回收中心、自建/委托选项、容量和成本；
3. 在 `processing_facilities.csv` 中设置梯次利用与再生利用设施；
4. 在 `arcs.csv` 中提供候选节点之间的代理距离或道路距离；
5. 在 `configs/` 中设置当地服务半径、承接率、分流比例、设施数量和成本情景。

标准化输入表的核心字段如下：

| 文件 | 作用 | 关键字段示例 |
| --- | --- | --- |
| `regions.csv` | 来源区域与回收规模 | `region_id`、`lon`、`lat`、`retired_battery_tons` |
| `collection_options.csv` | 候选中心及组织方式 | `collection_id`、`mode`、`capacity_tons`、固定/单位成本 |
| `processing_facilities.csv` | 梯次与再生处理设施 | `type`、`capacity_tons`、`shared_capacity_tons`、成本 |
| `arcs.csv` | 节点间运输关系 | `origin_id`、`destination_id`、`proxy_km`、`osrm_km` |
| `baseline.yaml` | 基准规划条件 | 承接率、服务半径、容量、成本、求解精度 |

当前代码保留了广东案例的 P01 扩容扩展。应用于其他地区时，可将当地既有核心设施映射为相应案例设施；如果没有此类设施，应关闭扩容情景或将该扩展改为当地配置。全国适用指模型框架和输入接口可迁移，不表示仓库已经提供全国企业级基础数据。

## 广东示范情景

广东案例用于验证全国通用框架能否在真实空间尺度下完成输入构建、路网距离处理、设施选择、流量分配、成本核算和情景分析。

`results/scenario_summary.csv` 中的 `baseline` 行显示：网络进入量为 3,516.584 吨，正常网络处理约 3,210.991 吨，应急外包约 305.593 吨（8.69%），年度总成本约 6,882.25 万元。以上均为公开代理数据与情景假设下的模型结果，不是企业实际经营数据。

仓库保存 49 组正式 OSRM 情景和 1 组代理距离基准对照，可用于分析规模、承接率、空间权重、运输价格、服务半径、组织方式、合作容量、最低处理量和设施扩容等因素。

## 输入与输出

模型输入包括来源规模、空间分布、候选设施、处理能力、固定与单位成本、运输距离、服务半径、承接率、梯次利用比例和情景参数。

运行后生成：

- `scenario_summary.csv`：各情景的总成本、单位成本、设施数量、应急外包及求解状态；
- `scenario_collections.csv`：被选中的区域中心、组织方式、处理量和利用率；
- `scenario_processing.csv`：被选中的后端设施、处理量和利用率；
- `scenario_flows.csv`：每条正流量路径的数量、距离和吨公里；
- `scenario_costs.csv`：年度成本分项；
- `validation.json`：约束校验、求解状态和一致性检查；
- `results/figures/`：网络布局、成本构成和敏感性分析图。

## 快速开始

要求 Python 3.11 或更高版本。依赖版本已锁定在 `requirements-lock.txt`：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-lock.txt
python scripts/reproduce_results.py
python -m pytest -q
```

Windows PowerShell：

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-lock.txt
python scripts/reproduce_results.py
python -m pytest -q
```

若要从案例工作簿重新生成标准化输入：

```bash
python scripts/reproduce_results.py --workbook "/path/to/案例数据集.xlsx"
```

正式广东情景使用 OSRM `driving/car` 路网距离；Haversine 代理距离用于数据预检查、对照和诊断。结果默认写入 `results/`，不会修改原始工作簿。

## 可视化网站

在线地址：<https://fleur23-rgb.github.io/china-ev-battery-reverse-logistics/>

网站默认提供“全国空白模板”，用户可以填写任意地区的退役规模、中心能力、运输距离和成本参数；也可以载入“广东省·论文参考案例”作为示例。页面会即时展示建议节点数量、能力缺口、应急外包比例和成本构成。

网站采用便于交互的参数化测算逻辑，不会在浏览器中完整运行 MILP。需要设施级选址、逐路径流量和论文级复核时，应运行 `src/` 中的 Pyomo + HiGHS 模型，并检查 `validation.json`。

## 仓库结构

| 路径 | 内容 |
| --- | --- |
| `src/` | 通用数据读取、Pyomo 模型、求解和校验代码 |
| `scripts/` | 输入构建、基准运行、批量情景和网站数据导出 |
| `configs/` | 广东示范情景及敏感性配置 |
| `data/` | 广东 V2.1 案例工作簿和标准化输入示例 |
| `results/` | 当前 OSRM 正式结果及代理距离基准对照 |
| `results_proxy_v7_4/` | 历史 V7.4 代理距离结果，仅供版本对照 |
| `tests/` | 输入、变量、约束、成本和结果一致性测试 |
| `web/` | 全国参数化可视化网站源码 |

`data/raw/` 与 `data/processed/` 分别是原始案例工作簿和模型可读输入，并非重复文件；`web/public/data/model-results.json` 是静态网站运行所需的数据副本。历史 V7.4 代理结果与当前 OSRM 结果口径不同，因此保留为版本对照。

## 适用边界

- 当前模型为单期、单类总量规划模型；
- 未内置全国各地区退役量、企业设施和危运路线数据库；
- 未纳入电池包级健康状态、收购价、产品销售收入、多期库存及随机回流；
- 坐标和部分设施参数采用公开代理，不等同于企业调度台账；
- OSRM `driving/car` 路径不是危险货物运输合规路线；
- 求解结果可能因操作系统、求解器版本和浮点容差出现极小差异。

因此，本模型适合战略与战术层面的网络方案比较，不应直接替代企业投资决策、合规路线审核或运营调度系统。
